## P1：需优先处理

### A01 · 普通信息文字与业务字段标签对比度不足

- **类别**：可访问性。
- **位置**：`web/style.css:816` 全局 label、`:695`及`:708–724` 商品 SKU 继承色；`web/refinement.css:69`、`:75` 导航分组，`:167` 小标题，`:382` 图例，`:590` 页脚，`:642` 门户引导文字，`:710` 商品分类。
- **复现**：打开客户与跟进→新增客户；另看总览、英文产品目录。
- **证据**：11px 表单标签 #75866d / 白底为 **3.90:1**；导航分组为 **3.78:1**；图例“上述订单已收”为 **4.28:1**；商品分类为 **4.23:1**；6个 SKU 为 **2.44–2.85:1**；8px页脚说明为 **3.59:1**。这些字段和说明不是品牌标志或纯装饰。
- **影响**：低视力用户更难辨认字段用途、产品编号和说明；小字号加重困难。
- **标准**：上述普通文字低于 WCAG 1.4.3 的 4.5:1 要求。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- **建议**：先修正标签、SKU、分类、图例和说明的语义颜色；以实际相邻背景复核，而非只检查按钮/正文。可使用 `$impeccable harden`，最终 `$impeccable polish`。

### A02 · 共享表单关闭按钮及合同上传控件无可访问名称

- **类别**：可访问性。
- **位置**：`web/main.tsx:3406` 新建/编辑表单头部关闭按钮；`web/main.tsx:3832` 合同 PDF 文件输入框。
- **复现**：新增客户表单中，第一个按钮只有 Lucide X SVG；合同档案中的 file input 没有 label、aria-label、aria-labelledby 或 title。
- **证据**：运行 DOM 的 unnamed 列表分别命中 `<button class="icon-btn">…</button>` 和 `<input … type="file" name="file">`。同一共享表单可能影响多个业务入口，本轮直接验证新增客户实例。
- **影响**：辅助技术无法可靠说明关闭按钮的用途，也无法将文件选择与“合同PDF”语义关联；键盘焦点能到达不等于控件有名称。
- **标准**：WCAG 4.1.2；文件输入也涉及标签关联。[W3C 名称、角色、值](https://w3c.github.io/wcag/understanding/name-role-value.html)。
- **建议**：图标关闭按钮提供随语言切换的名称；文件输入增加可见且关联的标签及类型/大小说明。保留已通过的焦点循环和返回行为。建议 `$impeccable harden`。

### A03 · 切换英文后文档语言仍为中文

- **类别**：可访问性 / 双语实现。
- **位置**：`index.html:1` 固定 lang="zh-CN"；`web/main.tsx:182` 语言状态与 `:1248` 切换按钮。
- **复现与证据**：点击 EN 后标题为 Overview，英文门户标题为 Products，但 `document.documentElement.lang` 仍是 `zh-CN`；源码没有将语言状态同步到该属性。
- **影响**：屏幕阅读器可能以中文读音规则朗读英文主体，语言识别和翻译工具也会得到错误信息。
- **标准**：WCAG 3.1.1 页面语言；混合语段还需考虑3.1.2。[W3C WCAG 2.2](https://www.w3.org/TR/wcag/#language-of-page)。
- **建议**：语言状态统一驱动 html lang；中文登录页和退出后的页面同步恢复；保留真正混合语段所需的局部语言标记。建议 `$impeccable harden`。

## P2：下一批处理

### A04 · 英文商品目录的分类标签仍显示中文

- **类别**：实现一致性 / 本地化。
- **位置**：`web/main.tsx:1624` 分类筛选已有英文映射；`:1651` 卡片直接输出 p.category。
- **复现与证据**：英文筛选显示 Everyday gifts / Travel / Office / Packaging，但六张商品卡仍显示“日用礼品、商务出行、办公文具、包装配套”。
- **影响**：英文客户无法把卡片类别与当前英文筛选可靠对应；同一概念出现两套语言。
- **建议**：抽取统一分类显示函数，让筛选和卡片共用；未知分类保留明确回退，不擅自改写业务主数据。建议 `$impeccable clarify`。

### A05 · 主题覆盖保留了旧颜色，颜色语义不集中

- **类别**：主题 / 实现一致性。
- **位置**：`web/main.tsx:34–37` 依次导入四份CSS；`web/refinement.css:5–6` 将 --green/--teal 改为钴蓝；`web/style.css:816` 标签及`:695–724`商品编码保留旧绿色/灰绿色。
- **证据**：refinement.css 中有190行 color/background 声明（含变量引用，不能当作190个硬编码颜色）；运行界面中新表面与旧标签/SKU色实际混用，且导致A01中的对比度问题。
- **影响**：后续调整主题需要追踪多层覆盖，容易只改背景、遗漏文字；颜色名称与作用不符增加维护误判风险。
- **建议**：在不改变当前视觉方向和统一浅色统计卡要求的前提下，整理 accent/text-muted/surface/status 等语义变量；区分 screen 与 print，逐步消除重复覆盖。建议 `$impeccable document` 先记录实际使用关系，再用 `$impeccable polish` 做有限归一。本项不要求新增暗色主题。
