# Vesta 界面样式维护

VESTA-330按320审计整理。保持现有系统字体、石墨色文字、蓝色操作色和统一浅色统计卡；此文记录实际实现，不引入新视觉方案。

## 样式职责

| 文件 | 负责内容 | 修改边界 |
| --- | --- | --- |
| `web/tokens.css` | screen下唯一基础主题：文字、表面、强调色、表单边界、反馈状态、覆盖层与字号 | 跨组件的语义值在这里定义，不在组件规则中重新声明同名基础变量 |
| `web/screen.css` | screen下布局、组件、交互状态和响应式规则 | 使用主题变量；仅在响应式断点覆盖布局变量，如sidebar-width |
| `web/print.css` | print下完整文档布局与固定打印配色 | 独立于屏幕主题；改动必须检查正式报价打印，不用屏幕截图替代打印证据 |

入口只导入以上三份文件，已移除style/prototype/parity/refinement四份历史覆盖文件。迁移按相同媒体条件、相同选择器、相同属性清除被后文覆盖的声明，保留不同选择器的优先级及简写/长写顺序；屏幕清除394条、打印清除88条。不能为了减少行数任意移动组件规则或合并不同断点。

屏幕的基础root声明集中到tokens；green/teal旧别名已从屏幕规则移除，操作色统一使用accent。打印保留自己的旧绿色文档配色，不跟随屏幕主题。局部插画/图表、阴影透明度及少量组件专用色可以留在组件规则中，不为单次使用创建无意义变量。

| 语义 | 当前值 / 用途 |
| --- | --- |
| accent / accent-hover | #2855d9 / #2046b8，操作及焦点 |
| control-border | #7c8797，空输入框对白色约3.64:1 |
| control-readonly | #f5f6f8，只读字段表面；仍可选择内容 |
| status-success-* / status-warning-* | 成功与待处理状态，保留文字状态，不只靠颜色 |
| status-error-* | 错误提示及aria-invalid字段边界 |
| notice-* / toast-surface | 信息提示与成功反馈 |
| dialog-overlay / navigation-overlay | 弹窗与移动导航遮罩 |
| text-meta / text-ui | 辅助文字12px / 常规控件文字13px；手机输入仍16px |

禁用字段保留可辨识边界，并有disabled原生状态和not-allowed指针；只读与错误状态有独立样式。强制颜色模式沿用系统配色，未使用forced-color-adjust:none。错误样式依赖真实aria-invalid状态，不自动把所有空的必填字段显示成错误。

## 手机导航契约

`web/mobile-navigation.ts`在不超过760px的管理端使用覆盖式导航，桌面及客户门户保持常驻导航。

- 打开：聚焦当前导航项，将背景兄弟节点设为inert；aside提供dialog语义和名称。
- 键盘：Tab/Shift+Tab循环，Escape关闭；移出焦点会被带回导航。
- 关闭：可用内部关闭按钮、右侧遮罩、选页、退出登录；恢复之前的inert状态与触发按钮焦点。
- 跨到桌面：收起覆盖状态，恢复背景，焦点放到桌面当前导航项；回到窄屏不自动重开。
- 事件监听在关闭或卸载时清理。`ModalAccess`统一管理弹窗及导航的页面滚动锁，避免两个组件互相覆盖overflow。

## 打印与回归

迁移前后20组DOM计算样式抽样：纯迁移差异仅为鼠标悬停取样差异；最终屏幕差异集中于预期边界色及悬停色，未出现布局属性差异。表单print媒体计算样式相同。正式报价52元素的打印样式最初也与基线相同，但渲染发现基线本身空白，故不能把“等价”视为“可用”。

旧打印选择器假定正式报价属于最后一个modal-backdrop，而详情弹窗可能在DOM中排在它之后。已改为通过`:has(.quotation-document)`定位报价覆盖层，不依赖兄弟顺序。基线报价visibility为hidden，修复后visible；已查看实际打印媒体截图并生成一页A4 PDF。操作系统打印对话框、物理打印机和多页长报价仍需单独验收。

完整打印规则独立保存带来约4.9kB gzip CSS增加（总量约16.6kB），用于避免屏幕主题修改改变文档样式；后续精简打印规则应基于更多单据覆盖，不能盲删。没有增加依赖。

每次调整共享样式至少复核登录、管理总览、表单、客户目录，检查桌面与320/390/760/1024px断点；涉及打印时打开已有正式报价，检查内容而不只检查构建成功。VESTA-330本机证据在`.local/verification/harden-330/`，测试数据均为虚构数据，不提交数据库、PDF、截图或构建产物。

## VESTA-360 响应式记录与披露

`mobile-records`仅用于客户、订单和总览重点订单；760px及以下将同一表格DOM按记录排布，使用单元格data-label呈现列名，第一项身份和最后一项操作占整行。桌面继续表格布局，不复制两份可交互记录。门户主导航在同一断点两列展示，订单工具栏搜索独占一行。

`portal-account`和`pricing-note details`使用原生details/summary，模拟/过期/失败状态在折叠区外；`more-actions`只收起低频操作，保留原有业务原因表单。弹窗焦点循环包含summary及未禁用字段。产品目录只保留一份h1，商品名称使用h2；屏幕及打印对应选择器同时更新，正式报价的打印规则未改。

采购草稿状态由App持有，RequestDialog不再在挂载时复制初始数量；关闭、追加产品及语言切换保持编辑，清空需确认。提交中锁定字段和关闭入口，失败保留；退出/刷新清理，不加入localStorage或sessionStorage。

## VESTA-370 组件与交互归属

- `web/records-table.tsx`统一主列表、workspace和parity表格的语义、列标签与空状态。`data-action`明确标记操作列，手机仅操作列隐藏字段标签，不能再把任何最后一列当作操作。语言通过RecordsLanguage上下文传递，不在渲染时读取尚未更新的html.lang。
- `web/record-navigation.tsx`承载详情位置、按钮与快捷键；调用方持有打开时的ID顺序，只保留当前数据里仍授权的ID。边界不循环；输入框、失焦或inert底层弹窗不响应快捷键。正文滚动随记录重置，原列表筛选和触发点不变。
- `web/modal-access.tsx`恢复焦点前检查目标仍连接、可用且属于下一活动弹窗；旧触发点随中间弹窗移除时，回退到当前弹窗，避免焦点落到body。
- `web/form-loader.tsx`只在打开编辑表单时加载`form-modal.tsx`与Decimal；失败给出重试，卸载后忽略晚到的加载结果。类型在`form-types.ts`，原有字段与金额计算规则保留。
- `.record-navigation`、`.priority-title`、空状态、采购撤销和数量反馈由screen.css负责。数量动画180ms，仅no-preference启用；减少动态时仍保留文字/数量/撤销反馈。
- DESIGN.md记录复用的实际tokens，sidecar包含16组8阶展示色带与8个独立组件片段；色带仅为面板元数据，不自动成为业务界面的额外颜色。后续变更同步两份设计文件。
- 清除screen/print中没有组件调用的orbit旧规则；打印登录统计继承字体，正式报价文档规则未改变。正式报价52元素、打印媒体图和A4 PDF已复验；仍不等于系统打印或多页验收。
- live仅使用本机Vite热更新，临时注入、方案包装及helper服务在结束时清理；`.impeccable/live/`仅config.json进入候选文件，token、根路径和会话日志由.gitignore排除。

## VESTA-380 登录动效（历史方案，已由390替代）

`web/login.css`是登录页限定样式，入口在screen.css之后、print.css之前导入；所有选择器限于login-gateway或专用journey/audience名称，仅screen媒体，不改变工作台或打印。不是新增全局主题层。`web/login-journey.tsx`提供业务流程SVG，静态轨道始终存在；800ms描线按当前入口重启，页面隐藏暂停，reduced-motion不运行。1000px以下隐藏图，手机只保留260ms入口连续切换，减少动态时直接定位。

双入口用原生button和aria-pressed，键盘Tab/Space可用；手动凭据跨入口保留，预置演示账号可随入口更换，权限仍由后端决定。登录请求处理中禁止修改字段、入口与演示选择。验证应包含两个真实演示账号、401恢复、重复切换及密码重置页面，不能只检查动画截图。

## VESTA-390 当前统一登录

`web/login-brand.tsx`替代已删除的login-journey，绘制几何V与矢量字标，重播按钮只重建SVG，不重挂载表单；无角色选择状态。`web/login.css`限定screen媒体与login-brand-page/brand专用类，沿用钴蓝、石墨、冷白，深色只作用于登录页。800ms折面、1100ms轮廓与200ms延迟后的800ms字标均单次播放；visibilitychange暂停，减少动态显示静态完整品牌，无依赖或持续循环。600px以下上下排列，600px以上左右排列。

统一表单保留可见标签、自动填充、错误保留输入、提交锁定及密码恢复；默认空白，无演示角色按钮。跳转仍由onLogin收到的logged.role决定，不根据输入用户名推断角色。验证须用buyer与owner实际登录，同时覆盖手机、键盘Enter提交、Space重播、401恢复及reset页面。

## VESTA-400 立体折光增强（当前动效）

在390统一登录基础上，LoginBrand使用SVG几何侧面/倒角及线性材质反射，CSS透视由brand-tilt承载。useId隔离SVG填充与裁切引用；无WebGL、第三方动画依赖或外部图片。V本体900ms有限入场，边缘光延迟100ms后1600ms单次掠过，保留原字标与轮廓描线；不再使用390分离折面入场。

指针事件只接受mouse并要求fine/hover及no-preference；局部归一化坐标限制在±1，旋转范围X为2–14度、Y为−22至−2度，固定Z为−3度。requestAnimationFrame按85ms时间常数平滑，目标误差小于0.002即停，无永久循环或永久will-change。光线平移跟随同一坐标，表单不位移。visibilitychange与IntersectionObserver暂停并归位，媒体偏好变化和卸载清理帧与监听器；无IntersectionObserver时仍保留隐藏页面处理。reduced-motion停用全部品牌动画，触摸不驱动指针动画；没有透视支持时SVG仍完整可见。

验证证据位于.local/verification/overdrive-400：check.cjs覆盖两类真实演示账号登录、失败恢复、reset及10档宽度；motion.cjs覆盖鼠标矩阵变化/归位、空闲无新增RAF、连续5次重播、离屏暂停、动态切换reduce、触摸与手动禁用3D的降级。帧采样属于本机无头Edge，不能替代中端手机真机帧率与多浏览器验收。

## VESTA-410 经营总览顶部密度

main.tsx仅在dashboard页标题添加overview-heading。screen.css用.page-heading.overview-heading限定标题组底距12px，h1顶距0、说明顶距6px；不改变其他业务页面标题间距。overview-control至统计卡12px，手机选择器最小44px且不收缩。DOM阅读顺序保持标题→说明→统计口径/币种→统计卡，无固定高度、负边距、定位覆盖或隐藏文案。

浏览器测量：桌面标题至币种栏30→12px，手机24→12px；标题说明10→6px、h1顶距8→0px、币种栏至卡片16→12px，桌面统计区上移34px；手机选择器37→44px。320/390/760/768/1024/1440/1920无横向溢出，英文/长说明自然换行，币种切换有效。证据.local/verification/layout-410，机械layout扫描前后均无发现；本轮不改变数据/权限/打印或登录页。
