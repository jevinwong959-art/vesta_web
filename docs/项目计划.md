# Vesta 网站项目计划

版本：1.3；确认日期：2026-11-07（Asia/Shanghai）。

## 目标与边界

为 Vesta 建设本地完整前后端 Demo：内部 CRM＋中英文客户门户。先完成并验证功能，再申请公司域名和采购云资源。原始 `CRM销售管理系统_演示Demo.html` 保留，只作为页面及业务参考。

首期覆盖客户、产品、询价、报价审批、订单、分批生产/发货/签收、单仓成品库存、分次回款/核销、合同档案、提醒、邮件捕获、导入导出及审计。暂不建设公开官网，不接真实支付、银行、ERP、工厂、物流、电子签章、多仓及复杂退换货。

全程使用虚构数据。默认约 5–30 员工；业务验证优先于时间估算。完整首期原估算 10–14 周，不代表当前已完成或自动承诺交付时间。

## 技术与运行

- React＋TypeScript 前端、NestJS API、PostgreSQL；模块化单体。
- 本地前后端由 Node 运行；Docker Compose 提供 PostgreSQL、S3 兼容私有附件存储及邮件捕获服务。
- 默认仅监听 127.0.0.1，不对互联网公开。本机服务停止时提醒及汇率暂停，启动后去重补查。
- 环境变量区分本地/测试/生产，实际凭据不入库；提供 `.env.example`。
- 统一 REST `/api/v1`；操作接口表达业务动作，不允许前端直接指定任意业务状态。
- 金额采用精确计算；CNY/USD 分别统计。UTC 存储时间，北京时间执行业务日历。
- 远程仓库：https://github.com/jevinwong959-art/vesta_web；用户在 2026-11-07 明确提供。保留历史，禁止强推。
- 本地 Git 提交记录任务编号；代码与进展一起形成检查点。

实际安装命令、端口、账号及环境差异记录于进展和运行手册；环境缺少 Docker 时先核查可行替代，明确记录而不假报数据库已验证。

本机无 Docker，增加可选便携 PostgreSQL 启动方式（项目内 `.local` 持久化，不安装系统服务）。Demo 数据采用 PostgreSQL records 表按实体类别保存 JSONB，并以事务锁串行化业务写入，保障小规模演示的一致性；生产前需按容量测试评估实体约束、索引及锁粒度。本地附件及邮件捕获允许使用文件/数据库适配器，不要求 Docker 才能运行；正式环境接入 OSS/邮件服务。

## 业务规则

1. 询价→报价草稿→冻结版本审批→发布→客户接受→订单→核实预付款→分批生产/发运→签收→结清。
2. 角色限制和客户隔离必须在后端执行，导出和附件同样受控。
3. 普通报价需非本人经理审批；经理发起由管理人员审批；管理人员发起由经理独立审批。无合格审批人不得发布。
4. 初始风险阈值：人民币等值 10 万元、低于参考价九折、毛利低于 20%、预付低于 30%，增加管理人员审批；均需上线前由业务确认。缺成本/汇率时不可完成依赖它的核价。
5. 提交审批后冻结价格、成本、客户及汇率快照；修改生成新版本重审。已过期/退回/作废/未发布报价不得接受。
6. 重复接受同一报价只生成一个订单。订单保留成交快照，产品和客户后续修改不回写历史。
7. 订单金额支持商品、折扣、运费及其他费用；保存贸易条款、港口、交期、税费说明，不自动计算各国税费。
8. 实际已核实预付款达到约定金额后释放生产。累计生产、发货、签收不得超过其上游数量及订单有效数量。
9. 库存记录实物、预留及可用数量；入库、预留、出库使用事务，阻止负库存及重复扣减；异常调整审批。
10. 收款原始记录与订单分配分离，一笔付款可分配多订单，分配总额不超过收款。同一交易不得重复登记；错误核销以反向记录冲正而非删除。
11. 全部签收且应收结清才完成订单；履约与资金状态分开。
12. 附件私有，合同上传与签署状态不等于电子签章。上传做类型、大小校验；正式上线需恶意文件检测。
13. 站内提醒周期：订单/报价 3 天、潜在客户 7 天、成交客户 30 天、升级 2 天、审批 24 小时。人工下次跟进优先，已读不重置时钟。
14. 任务持续运行、轮次去重、失败有限重试，启动补查。邮件首期只进入本地捕获页面。

## 自动汇率

- Frankfurter v2，每日参考 USD/CNY，后台北京时间 09:00 检查；当天未查则启动补查，管理可手动刷新。
- 记录货币对、值、来源口径、数据日期、抓取时间、版本。相同来源/日期/值去重；修订新增版本。
- 新草稿带入最新值；保存后不静默更新，用户主动采用新版本。审批锁定、转单继承、历史不回写。
- 人工汇率保存管理操作者及原因，只供明确选用的单据使用，不覆盖自动值。
- 失败保留旧值并展示状态；周末旧日期不等于失败。超过 7 个自然日需管理确认旧值或人工值；无值阻止相关核价。
- 离线种子明确标注模拟。实际结算汇率与参考汇率分开。
- 请求超时、有限重试；不能阻塞网站。
- 来源：https://frankfurter.dev/ ，条款：https://frankfurter.dev/license/ 。参考数据不等于银行成交价。

## VESTA-200 产品展示币种与参考汇率联动（2026-11-07）

用户新确认：中文产品目录展示人民币、英文展示美元，替代180中“客户约定币种优先”的目录显示规则。客户档案约定币种不被修改；新申请初始币种跟随语言，用户可显式另选。已保存报价、订单和财务统计继续使用单据币种与历史快照。

选有效自动参考数据，无真实值时允许清晰标注模拟值；人工汇率仅作用于明确选用的报价，不全局覆盖。未来/非正数/标记无效汇率拒用，无可用汇率显示美元不可用，不能用0或旧固定美元价冒充。产品页面标明来源、日期、失败和过期；语言切换/回到页面及可见页面每60秒同步后台现有参考价，不额外高频请求供应商。

报价草稿默认使用当前产品参考价；切换币种显式换算单价及运费/费用/折扣。选择汇率后可主动采用产品参考价；后台更新不静默重算已保存草稿。提交后冻结规则不变。
