# 原始 Demo 对照检查与本轮修订

日期：2026-11-07；任务：VESTA-120 / VESTA-130。参考原始 `CRM销售管理系统_演示Demo.html` 的页面渲染、客户档案和跟进表单，以及用户提供的客户页截图。原文件未修改。

## 结论

此前版本实现了后端核心流程，但页面信息被过度简化，尤以客户维护、总览和产品表现最明显。本轮以原型的信息结构和视觉样式为参照修订，保留真实登录、后端权限与数据库。不是逐像素复制；真实版本额外包含汇率、邮件捕获及独立审计页面。

| 页面 | 发现的问题 | 本轮处理 |
|---|---|---|
| 登录与角色 | 七类角色增加本地体验成本 | 用户确认合并四类；管理接财务/账号，经理接生产仓储；接口与历史账号同步迁移 |
| 经营总览 | 宣传横幅、记录数量和提示代替经营信息 | 恢复原币金额/回款/余额、业务阶段、近六个月订单与已收趋势、待办、近期订单 |
| 客户与跟进 | 缺统计、分级、下次维护、负责人显示原始 ID；全局备注表难以阅读 | 三项统计、状态/到期筛选、客户分级/行业、负责人姓名、档案、年度原币小结、采购汇总、历史订单与沟通时间线 |
| 跟进表单 | 只有摘要与下次日期；补录会错误重置维护时间 | 沟通方式、实际时间、摘要/下一步、下次计划；客户与单据独立，可明确同步；旧记录只入历史 |
| 产品与价格 | 所有产品使用通用包装图标，内部卡片不便比较 | 提取原型六种静态 SVG 示意图；内部产品表呈现价格/MOQ/交期/库存，门户保留商品卡片 |
| 询价申请 | “发起询价”和“采购需求”被误认为不同流程 | 统一为询价申请；产品页为预选商品快捷入口，列表为集中受理；增加状态和关联报价入口 |
| 报价与审批 | 缺少筛选与进度概览 | 恢复草稿/审批/发布说明、状态筛选及统计；保留真实版本冻结、独立审批、授权发布、打印 PDF |
| 订单履约 | 所有进行中业务显示为“履约中”，无法区分阶段 | 显示预付款/释放/生产/运输/签收待尾款/完成，发货比例条和统计；补五种可继续操作的场景 |
| 回款管理 | 缺按币种应收总览 | CNY/USD 余额分别统计、待核实数量；管理核实、冲正，销售登记线索 |
| 库存台账 | 规则说明、数量概览不足 | 商品数、实物/预留/可用量；经理负责入出库及申请，管理审批调整 |
| 合同档案 | 版本列表缺概览 | 合同版本数、签署数、关联订单数；保留真实私有 PDF 与授权下载 |
| 待办与提醒 | 缺状态概览和业务解释 | 待处理/未读/升级统计，说明已读不等于完成；后台扫描仍独立于浏览器 |
| 汇率、邮件、审计 | 样式与主业务不统一 | 统一页头、表格、颜色、留白与筛选；这三页为真实实现新增，不强行套用原型中没有的页面 |
| 权限与设置 | 角色不直观、设置页套用了无意义的记录筛选 | 四角色职责矩阵、账号管理和规则配置，去掉无意义筛选条 |
| 客户门户 | 沿用“经营总览”“报价审批”等内部名称 | 客户中心、产品目录、我的询价/报价/订单/合同；独立欢迎卡与公司数据，保留中英文切换 |

## 数据与验证

- `pnpm demo:data` 幂等追加 6 客户、5 订单及相关历史记录、模拟客户账号 buyer_demo，不清空原库。原两位客户保留，现总数 8；5 位已成交，3 位维护到期（取决于实际运行日期和后续操作）。
- 五张订单为 DEMO-SO-1/2/3/4/6，分别展示待预付款、分批生产、分批发运、签收待尾款和结清完成；记录均为虚构。
- 15 项集成测试通过：权限/客户隔离、独立审批、回款和库存、跟进补录/独立时钟/同步、模拟数据幂等与金额/数量对账、角色迁移等。
- 浏览器检查管理角色全部 14 个导航页面、客户档案及跟进表单；客户门户商品卡片与 buyer_demo 单公司订单。上述检查无页面报错，控制台未发现错误。
- 1440px 桌面检查；390px 窄屏客户页无整页横向溢出，宽表格在容器内滚动。

## 保留的差异与后续验收

- 原型为浏览器内模拟切换身份，真实版本必须退出后登录相应账号。
- 原型客户门户使用顶部导航，当前保留统一侧栏并在手机折叠菜单；公司卡片、商品插画与业务命名已对齐。没有宣称所有页面逐像素一致。
- 原型支持购物篮多商品申请；当前询价入口为单商品申请，报价本身支持多商品。本轮统一入口未把单商品申请扩展为购物篮。
- 本轮没有为模拟订单伪造已签署合同文件；合同上传仍需通过授权账号操作。
- 页面逐页打开与 API 测试不等于所有按钮、所有角色的完整页面闭环验收。原计划中完整多角色页面链路、历史订单/期初库存应收导入及正式上线验收仍待后续任务。
