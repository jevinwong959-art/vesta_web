# vesta网站搭建

默认项目位于 `D:/vesta_web`。若用户提供新位置，以该位置为准；找不到时先定位包含两份项目文档的目录，不创建一个空替代项目。

## 恢复工作

1. 阅读项目根目录 `AGENTS.md`、`docs/项目计划.md`、`docs/项目进展.md`。
2. 检查当前分支、最近提交、`git status --short`、工作区/暂存区差异及相关未跟踪源码。未建立 Git 时如实记录，不能假定没有代码。
3. 对照任务编号、测试记录与实际实现核实完成情况。文档落后于代码时保留改动、验证后补记；文档声称完成但证据不足时修正状态，禁止为了匹配文档而覆盖工作区。
4. 从当前检查点或依赖已满足的下一任务继续；开始前更新“进行中”、当前检查点和验收条件。

## 实施与记录

- 用户最新需求优先。遵守当前计划/执行模式及现有授权；Skill 本身不授予采购、公开部署或发送真实客户邮件权限。
- 首期为本地 React/TypeScript＋NestJS＋PostgreSQL Demo。原 HTML 是只读业务参考，不是认证或数据库实现。
- 后端负责权限、客户隔离、金额/库存事务和单据快照。每日参考汇率不能改写已冻结业务。
- 每个可独立验证的改动批次同步进展：任务编号、改动文件、实际命令和结果、未验证项、阻塞、下一步。实质需求/设计变化同时更新计划。
- 检查点提交包含对应代码及进展，使用任务编号关联；仅记录已有基线哈希，不在文档中要求本提交自己的哈希。
- 不提交密钥、数据库、上传文件或日志；不强推、不覆盖无关改动。用户已指定远端时先核对历史。
- 收尾前留下可执行的恢复步骤和运行方式。突然中断后依靠 Git 差异恢复，不假设进展文档始终最新。

Skill 仓库源码在 `skills/vesta-website-build/`，安装副本在 `~/.codex/skills/vesta-website-build/`。仅维护这一个逻辑 Skill；更新后同步副本并运行 skill-creator 的 quick_validate.py。不要把业务计划复制进 Skill。
